Folder Size Browser

Drill-down disk-usage explorer for Windows — find what's eating your space
zero install · zero cost

The idea

Your C: drive is filling up and you want to know where it went — without installing WizTree or TreeSize. One PowerShell script turns the terminal into a navigable map: it opens at C:\, lists every folder with its total recursive size biggest-first, and lets you walk down into whatever's fat until you find the culprit.

How it works

robocopy /L
the sizing engine
List-only mode (copies nothing) walks each sub-tree far faster than Get-ChildItem and reports an exact byte total.
/XJ
skip junctions
Ignores junctions & symlinks, so nothing is double-counted and there are no infinite loops (the bug that made AppData read as 0).
size cache
instant re-visits
Measured folders are remembered, so Back and re-entry are instant. Press R to force a fresh re-scan of the current folder.

Run it

  1. Open at the C: drive (default)

    No arguments needed — it starts at C:\.

    powershell -ExecutionPolicy Bypass -File "C:\Users\bardi\Desktop\main\projects\ai_code_projects\folder-size-browser\FindBigFiles.ps1"

  2. Or open somewhere specific

    Pass any folder or drive with -Path.

    ... \FindBigFiles.ps1 -Path "D:\"

  3. Drill down to the fat

    Type a folder's number to open it; you're now inside it seeing its sub-folders and sizes. Keep going until you find what's eating space.

Troubleshooting

First scan of C:\ feels slow

Sizing huge system folders like C:\Windows takes about a minute. The progress bar shows which folder it's on. Every folder is cached afterward, so navigating Back is instant.

C:\Windows looks too big

Its WinSxS store uses hard-links that get counted per-link — every disk-usage tool shows this. It doesn't affect your personal folders.

"running scripts is disabled on this system"

That's the execution policy. The launch command includes -ExecutionPolicy Bypass to sidestep it for this one run without changing your system setting.

Don't touch the /L flag. The sizing call is robocopy <folder> <folder> /L ... — the /L makes it list-only (copies nothing). Remove it and robocopy would try to copy the folder onto itself.
